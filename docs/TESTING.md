# Testing and acceptance

Run `pnpm typecheck`, `pnpm lint`, `pnpm test:unit`, and `pnpm build`. `pnpm test:e2e:chromium` starts the fixture server and loads a temporary Chromium build whose manifest is granted **only** the local fixture origin. The production manifest still requests website access at activation. The browser test trains four fields, previews 20 records, traverses three pages, checks 60 unique JSON records and CSV/XLSX downloads, saves and reruns after a price selector/wrapper change and a record tag/class change, and verifies selector recovery. A second browser test covers Load More, infinite scroll, SPA routing, numbered links, URL pagination, duplicate records, dynamic classes, open shadow DOM, and nested scrolling. Export unit tests read XLSX back and check Unicode, CSV quoting, native numeric cells, and formula-safe text.

`pnpm test:parity` runs a worker journey against the same controlled site, expecting 60 unique records. `pnpm test:e2e:firefox` temporarily installs the Firefox MV3 build through Selenium and checks one-field training, preview, and 60 records across three pages. The standalone worker and Firefox scripts start the fixture server if it is not already running. Unit tests cover copied picker behavior and deterministic DOM inference/extraction cases. `apps/test-sites/main.ts` provides static, duplicate, dynamic-class, nested-scroll, open-shadow, and changed-structure variants for continued coverage.

Release checks should include real Chromium and Firefox builds, permission behavior, saved reruns, worker profile handling, export content, notices, and source-control secrets. The release script must not be treated as passed until every command exits successfully; see the README for remaining Firefox and recovery limits.
